## 1. Problem Statement

AI coding agents (Claude Code, OpenCode, etc.) routinely read project files (including `.env`, config files, output of CLI tools) and forward that content to the upstream LLM provider. Any secret in that content — API keys, database passwords, private keys, JWTs — leaves the user's machine and ends up in third-party logs and possibly model training data.

**opensecretmask** is a credential masker that intercepts the read direction (replace secrets with format-preserving placeholders before content reaches the LLM) and the write direction (restore real values before tools execute locally), via a small `osm` binary invoked by harness-native hooks.

**Non-goal**: secrets management, vaulting, rotation. Tools like `psst`, `1Password`, `vault` cover that. opensecretmask only protects against accidental leak through agent context.

## 2. Decisions Captured

| # | Decision | Rationale |
|---|---|---|
| D1 | Format-preserving mask (same prefix + length + charset class) | Model can't tell value is masked — fewer behavior changes than `[REDACTED]` markers |
| D2 | Source: `.env` auto-import + regex/entropy detection (no manual CLI required) | Zero-config UX matches `@rehydra/opencode` |
| D3 | Standalone Go binary + thin per-harness adapters; JSON over stdin/stdout | Universal portability, fast cold-start (~5–10ms), single static binary |
| D4 | v1 ships claude-code adapter only; protocol pre-architected for opencode/pi-agent/etc | Smallest deliverable that proves the multi-harness contract |
| D5 | Storage: plain JSON files, chmod 600, under `~/.opensecretmask/` | Simple, debuggable, defers encryption to v1.1+ |
| D6 | Stable cross-session masks: HMAC-SHA256(per-install key, secret) | Deterministic — model can reference same value across sessions. *Plaintext IS on disk in `secrets.json`/`mappings.json` (chmod 600); at-rest encryption deferred to v1.1 — see §10.2.* |
| D7 | User-prompt secrets: allow + warn via `additionalContext` (claude-code can't rewrite prompts) | Documented limitation of `UserPromptSubmit` |
| D8 | flock + atomic-rename for concurrent session safety | POSIX guarantees, single global `.lock` file |
| D9 | Hash: HMAC-SHA256 only (with HKDF-Expand for streaming) | Stdlib only, conservative, FIPS-aligned |
| D10 | macOS + Linux targets only for v1 | Where the userbase is; Windows revisit later |

## 4. Format-Preserving Mask Algorithm

### 4.1 Goal

Given a real secret value, produce a `mask` such that:
1. `len(mask) == len(real)`
2. `mask` shares the same prefix and same charset class as `real` (same regex still matches)
3. `mask` is deterministic given `(install_key, real)`
4. `mask != real` (collision-checked)
5. Mask is one-way *cryptographically*: given only `(mask, install_key)`, you cannot recover `real` (HMAC is preimage-resistant). Reversal in this system happens via lookup in `mappings.json`, NOT by inverting the HMAC — see §4.5.

### 4.2 Classification rules

```go
// internal/core/detector/patterns.go
// All charsets are deliberately restricted to delimiter-safe alphabets
// (no quote, no backslash, no shell-meta) so a mask body cannot
// break surrounding JSON/YAML/TOML/shell structure. See §8.6.
type Charset uint8
const (
    CharsetAlphanumeric Charset = iota // [A-Za-z0-9]
    CharsetHex                          // [0-9a-f]
    CharsetBase64URL                    // [A-Za-z0-9-_]
    CharsetAlphaUpper                   // [A-Z0-9]
    CharsetBase64                       // [A-Za-z0-9+/=] — ONLY for rules matching inside an already-base64 region (PEM bodies)
    // CharsetGeneric removed in v1: too unsafe for structured contexts.
    // Fallback rules (env-import, entropy-high) use CharsetBase64URL regardless of source charset.
)

type Rule struct {
    ID        string
    Pattern   *regexp.Regexp
    MinLen    int
    MaxLen    int   // upper bound; informs streaming overlap and container cap. 0 = use default.

    // Multi-line container hints: when both set, the streaming scanner
    // buffers from BeginMarker until EndMarker before scanning, instead
    // of relying on overlap. Used by pem-private-key, ssh-private-key.
    BeginMarker string
    EndMarker   string

    // Two mutually exclusive masking modes. Pick one per rule.
    // (a) FlatPrefix: preserve N leading chars, mask the rest as one body.
    //     Suitable for opaque tokens (Stripe keys, AWS access keys, GitHub PATs).
    PrefixLen int
    Charset   Charset

    // (b) Segments: preserve named delimiters/groups, mask only chosen capture
    //     groups. Suitable for structured secrets (JWT, PEM, conn strings).
    //     If non-nil, takes precedence over PrefixLen/Charset.
    Segments []Segment
}

// Segment describes one masked region inside a structured match.
// Pattern must contain a single non-overlapping capture group; the masker
// replaces only the captured text and preserves everything outside it
// (including delimiters, newlines, headers, footers).
type Segment struct {
    Name    string  // "jwt-payload", "jwt-signature", "pem-body", "conn-password"
    Group   int     // capture-group index inside Rule.Pattern (1-based)
    Charset Charset // alphabet to use for this segment's mask body
}
```

### 4.4 Mask function

Two modes: flat-prefix (opaque tokens) and segment (structured secrets). Both use:
- **Rejection sampling** to map hash bytes onto charset uniformly (no modulo bias).
- **Explicit error checks** on `stream.Read` (HKDF reader can fail in principle; we treat any error as a hard fault — fail-closed per §8.10).
- **Two-tier collision check**: against the real value AND against existing entries in `mappings.json.by_mask`. Domain-separator `0x01` byte appended on retry to derive a fresh body.

```go
// internal/core/transformer/fpe.go
package transformer

import (
    "errors"
    "fmt"
)

var ErrMaskExhaustedRetries = errors.New("opensecretmask: collision retries exhausted (8); aborting to avoid weak mask")

const maxCollisionRetries = 8

// Mask produces a format-preserving mask for `real` according to `rule`.
// `existing` is mappings.by_mask (read with RLock) for cross-secret collision check.
func Mask(real string, rule Rule, hasher *keymgr.Hasher, existing map[string]string) (string, error) {
    if rule.Segments != nil {
        return maskSegments(real, rule, hasher, existing)
    }
    return maskFlat(real, rule, hasher, existing)
}

// maskFlat: preserve PrefixLen chars, mask the rest as one body.
func maskFlat(real string, rule Rule, hasher *keymgr.Hasher, existing map[string]string) (string, error) {
    if len(real) < rule.PrefixLen {
        return "", fmt.Errorf("real value shorter than rule.PrefixLen (%d < %d)", len(real), rule.PrefixLen)
    }
    prefix := real[:rule.PrefixLen]
    bodyLen := len(real) - rule.PrefixLen
    cs := rule.Charset.Bytes()

    for attempt := 0; attempt < maxCollisionRetries; attempt++ {
        body, err := deriveCharsetBytes(hasher, []byte(real), attempt, bodyLen, cs)
        if err != nil {
            return "", fmt.Errorf("mask body derivation failed: %w", err)
        }
        masked := prefix + string(body)
        if masked == real {
            continue // self-collision (vanishing) — try with next domain-sep byte
        }
        if other, exists := existing[masked]; exists && other != real {
            continue // cross-secret collision — try again
        }
        return masked, nil
    }
    return "", ErrMaskExhaustedRetries
}

// maskSegments: mask only the captured groups in the pattern; preserve delimiters.
func maskSegments(real string, rule Rule, hasher *keymgr.Hasher, existing map[string]string) (string, error) {
    locs := rule.Pattern.FindStringSubmatchIndex(real)
    if locs == nil {
        return "", fmt.Errorf("rule %q did not match the input it was supposed to", rule.ID)
    }
    out := []byte(real)
    // Walk segments in reverse-end order so byte offsets stay valid as we replace.
    type span struct{ start, end int; cs []byte }
    var spans []span
    for _, seg := range rule.Segments {
        s, e := locs[2*seg.Group], locs[2*seg.Group+1]
        if s < 0 { return "", fmt.Errorf("segment %q (group %d) did not capture", seg.Name, seg.Group) }
        spans = append(spans, span{s, e, seg.Charset.Bytes()})
    }
    // Sort spans by start descending so later replacements don't shift earlier offsets.
    for i := 0; i < len(spans); i++ {
        for j := i + 1; j < len(spans); j++ {
            if spans[j].start > spans[i].start { spans[i], spans[j] = spans[j], spans[i] }
        }
    }
    for attempt := 0; attempt < maxCollisionRetries; attempt++ {
        candidate := append([]byte(nil), out...)
        for _, sp := range spans {
            // info = real || segment-name || attempt; ensures distinct streams per segment
            info := make([]byte, 0, len(real)+8)
            info = append(info, []byte(real)...)
            info = append(info, byte(sp.start), byte(sp.end))
            info = append(info, byte(attempt))
            body, err := deriveCharsetBytes(hasher, info, 0, sp.end-sp.start, sp.cs)
            if err != nil { return "", err }
            candidate = append(candidate[:sp.start], append(body, candidate[sp.end:]...)...)
        }
        masked := string(candidate)
        if masked == real { continue }
        if other, exists := existing[masked]; exists && other != real { continue }
        return masked, nil
    }
    return "", ErrMaskExhaustedRetries
}

// deriveCharsetBytes pulls bytes from the keyed XOF and maps them onto `cs`
// using rejection sampling to avoid modulo bias. `attempt` is appended to the
// HKDF info as a domain separator so retries produce a different stream.
func deriveCharsetBytes(hasher *keymgr.Hasher, info []byte, attempt, n int, cs []byte) ([]byte, error) {
    csLen := len(cs)
    if csLen == 0 || csLen > 256 {
        return nil, fmt.Errorf("invalid charset length %d", csLen)
    }
    // Largest multiple of csLen that fits in a byte; reject anything ≥ this.
    maxAccepted := (256 / csLen) * csLen
    if maxAccepted == 0 { maxAccepted = 256 } // when csLen == 256 → no rejection

    sep := append(append([]byte(nil), info...), byte(attempt))
    stream := hasher.Stream(sep)
    out := make([]byte, n)
    buf := make([]byte, 64)
    written := 0
    for written < n {
        nr, err := stream.Read(buf)
        if err != nil { return nil, fmt.Errorf("HKDF stream read failed: %w", err) }
        for i := 0; i < nr && written < n; i++ {
            if int(buf[i]) >= maxAccepted { continue } // rejection sampling
            out[written] = cs[int(buf[i]) % csLen]
            written++
        }
    }
    return out, nil
}
```

**Rationale**: rejection sampling avoids modulo bias (256 % 62 ≠ 0 → naive mod skews distribution; reject bytes ≥ `(256/csLen)*csLen`). `existing` map check stops silent reverse-lookup corruption from cross-secret collisions. 8-retry bound catches pathological cases (bug or attack) without infinite recursion. All errors propagated → hook layer fails closed per §8.10.

### 4.5 Unmask function

Unmasking is **lookup-based**, not cryptographic inversion. It needs the plaintext mapping table.

```go
// internal/core/transformer/unmask.go
// Multi-pattern Aho-Corasick replace using all keys in mappings.json.by_mask
// where mappings.json contains real plaintext values keyed by their masks.
// HMAC is one-way; the mask -> real mapping only exists because we persisted it.
func Unmask(text string, mappings *store.Mappings) string {
    return mappings.AhoCorasickReplace(text)
}
```

Implication: anyone with read on `mappings.json` has the secrets directly — the install.key is irrelevant for that path. This is acknowledged in §10.2 as a v1 tradeoff.

### 4.6 Properties

- Deterministic across sessions and installs (same install_key)
- Different secrets → uniformly distributed body in chosen charset
- Length exactly preserved (no length-class side channel)
- Cannot collide with real value AND cannot collide with another already-registered mask (`mappings.json.by_mask` is consulted before insert; collisions trigger re-derivation with a domain-separator counter, bounded to 8 retries)
- Reversal in normal operation requires `mappings.json` (the persisted lookup table); HMAC itself is one-way. `install.key` is required to *recompute* a mask from a known real value (e.g., to refresh mappings after key rotation), not to *invert* an existing mask

## 5. Hook Flow per Event

### 5.1 `PostToolUse` — mask tool outputs (read direction)

**Matcher**: `.*` (all tools, with detector fast-path for no-finding case).

```
stdin: { hook_event_name: "PostToolUse", tool_name, tool_input, tool_response, session_id, cwd }
  ↓ extract scannable text per tool (Read.content, Bash.stdout/stderr, Grep.matches, …)
  ↓ check skip_extensions (binary file paths) → exit 0 silently
  ↓ detector.Detect(text)
  ↓ if no findings → exit 0 silently  (zero-cost path)
  ↓ for each finding:
      - mappings.RLock + lookup
      - if not found: compute Mask(value), persist (Lock + atomic write)
      - replace in tool_response
  ↓ stdout: { hookSpecificOutput: { hookEventName: "PostToolUse",
                                     updatedToolOutput: <modified tool_response, same shape> } }
  ↓ append audit.log: { ts, session_id, action: "mask", count, rules: [...] }
```

`updatedToolOutput` MUST match original `tool_response` shape — adapter validates per-tool.

### 5.2 `PreToolUse` — unmask tool inputs (write direction)

**Matcher**: `Edit|Write|MultiEdit|Bash|NotebookEdit`.

```
stdin: { hook_event_name: "PreToolUse", tool_name, tool_input, session_id, cwd }
  ↓ identify unmask-candidate fields per tool:
      - Edit.new_string, Edit.old_string                          → permissionDecision: "allow"
      - Write.content                                              → permissionDecision: "allow"
      - MultiEdit.edits[].new_string, MultiEdit.edits[].old_string → permissionDecision: "allow"
        (BOTH halves of every edit — old_string is matched against on-disk content
         which holds real values, so any mask in old_string must be unmasked or
         the edit will fail to find its target)
      - NotebookEdit.new_source, NotebookEdit.old_source           → permissionDecision: "allow"
      - Bash.command                                               → see §5.2.1 (gated)
  ↓ mappings.RLock + load reverse map
  ↓ multi-pattern replace masked → real (Aho-Corasick)
  ↓ for Bash: classify command via §5.2.1 egress detector → ask | deny | allow
  ↓ if replacements > 0 →
      stdout: { hookSpecificOutput: { hookEventName: "PreToolUse",
                                       permissionDecision: <per-tool>,
                                       permissionDecisionReason: "<rule fired + sample mask IDs>",
                                       updatedInput: <full modified tool_input> } }
    else exit 0 silently
  ↓ append audit.log: { ts, session_id, action: "unmask", tool, count, decision }
```

`permissionDecision` must be one of `"allow" | "ask" | "deny"`; required to use `updatedInput`.

#### 5.2.1 Bash unmask gate (CRITICAL — egress prevention)

Bash is the one tool that can exfiltrate a real secret to anywhere on the internet. Naive unmask + auto-allow re-materializes the real value inside `curl`/`wget`/`nc`/`ssh`/etc — defeating the system. Gating ladder for `Bash.command` after mask→real:

```
classify(cmd, replacements):
  if replacements == 0:                         return SKIP   # silent passthrough
  if matchesEgress(cmd):                        return DENY   # real value would leave machine
  if hasSubshellOrEval(cmd):                    return DENY   # $(...), backticks, eval, source, . → arbitrary code
  if hasPipeOrRedirect(cmd):                    return ASK    # user confirms
  if cmd[0] in local_allowlist and no meta:     return ALLOW  # auto
  return ASK                                                  # default conservative
```

| Decision | Effect |
|---|---|
| `SKIP` | exit 0, no `updatedInput`; original cmd runs |
| `DENY` | `permissionDecision: "deny"` + reason; tool blocked; claude reformulates |
| `ASK` | `permissionDecision: "ask"` + `updatedInput`; user sees real secret + explicit approve |
| `ALLOW` | `permissionDecision: "allow"` + `updatedInput`; auto |

Egress + allowlist defaults (`[harness.claudecode.bash]`):

```toml
[harness.claudecode.bash]
default_decision        = "ask"
egress_blocklist        = ["curl","wget","http","httpie","xh","nc","ncat","socat","telnet",
                           "ssh","scp","sftp","rsync","ftp","openssl s_client",
                           "git push","git fetch","git clone","git pull","git ls-remote",
                           "gh","glab","aws","gcloud","az","doctl","fly","vercel","netlify","heroku",
                           "npm publish","pnpm publish","yarn publish","cargo publish","gem push","twine upload",
                           "docker push","podman push","helm push",
                           "kubectl apply","kubectl exec","kubectl port-forward",
                           "python -c","node -e","deno eval","ruby -e","perl -e"]
local_allowlist         = ["cat","head","tail","grep","rg","ag","awk","sed","sort","uniq",
                           "ls","fd","find","stat","file","wc","diff","jq","yq","xq",
                           "echo","printf","mkdir","mv","cp",
                           "git status","git diff","git log","git show","git add","git commit",
                           "make","just","task",
                           "npm install","npm test","npm run","pnpm install","pnpm test","pnpm run",
                           "bun install","bun test","bun run","cargo build","cargo test"]
treat_pipe_as_ask       = true
treat_redirect_as_ask   = true
treat_subshell_as_deny  = true
```

Documented heuristic limits:
- `curl http://localhost:...` blocked same as `curl https://attacker.com/...` (no host parsing). User can override per-pattern via `osm allow-cmd 'curl http://localhost:*'` or `permission_mode: bypassPermissions`.
- `bash -c '...'` evades top-1 token check → gate runs BOTH token-1 detection AND substring scan over full command for blocklist names. Defense in depth.
- `eval`, `source`, `.` (dot-source), `> /dev/tcp/*` → always `DENY`.

**Highest-risk surface in the system.** Conservative defaults; user relaxes via allowlist if too noisy. Errors lean DENY/ASK, never ALLOW.

### 5.3 `UserPromptSubmit` — warn-only

**Matcher**: empty (every prompt).

```
stdin: { hook_event_name: "UserPromptSubmit", prompt, session_id }
  ↓ detector.Detect(prompt)
  ↓ if no findings → exit 0 silently
  ↓ stdout: { hookSpecificOutput: { hookEventName: "UserPromptSubmit",
                                     additionalContext: "⚠ opensecretmask: detected N potential secret(s) in your prompt — type=…. Forwarded as-is. Consider retyping with placeholders." } }
  ↓ append audit.log: { ts, session_id, action: "warn", count, rules }
```

claude-code's `UserPromptSubmit` cannot rewrite prompt content. We intentionally do NOT block — warn-only per D7. Audit log captures the event for post-hoc visibility.

### 5.4 `SessionStart` — eager preload

**Matcher**: empty.

```
stdin: { hook_event_name: "SessionStart", source: "startup"|"resume"|"clear", cwd, session_id }
  ↓ walk cwd up until .git or filesystem root
  ↓ for each .env, .env.*, .envrc found:
      - parse KEY=VALUE
      - skip values < MinLen, in allowlist, or in ignore_keys
      - compute mask, register in secrets.json + mappings.json
  ↓ stdout: {} (silent — no context injection on start)
```

This prewarms the mapping store so PostToolUse hits the fast path immediately on the very first tool call.

### 5.5 Hook contract

- **stdin**: full claude-code hook JSON
- **stdout**: hook response JSON OR empty
- **exit code semantics** (claude-code-specific, important):
  - claude-code's `PostToolUse` hook treats **exit 1 as non-blocking** (stderr surfaced to claude, tool result still flows through). For our fail-closed mask path, exiting 1 would leak the original output. So we **never** exit 1 to indicate mask-side failure.
  - Mask-direction failures emit JSON: `{"decision": "block", "reason": "..."}` (PostToolUse) and exit 0. This is the only mechanism that actually withholds the original tool output.
  - Mask-direction "redact-all" emits `{"hookSpecificOutput": {"hookEventName": "PostToolUse", "updatedToolOutput": <safe-replacement-payload>}}` and exits 0.
  - PreToolUse failures emit `{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "..."}}` and exit 0 — but per §8.10 the unmask path defaults to fail-open (no JSON, exit 0) so the tool runs with the mask string and fails loudly.
  - Exit 2: claude-code-defined "block" semantics for some events; we do NOT use exit 2 because the JSON `decision` field is available for every event we touch and is more precise.
  - Exit 1 is reserved for **CLI misuse only** — unknown subcommand, malformed flags — surfaced before any hook payload exists. Never used once the binary has read a hook payload from stdin.
  - **Critical**: missing `~/.opensecretmask/install.key`, missing `~/.opensecretmask/`, lock-file corruption, broken config — these are *not* harness misuse, they are runtime preconditions that fail mid-hook. They MUST be handled like any other mask-side failure: emit JSON `{"decision":"block","reason":"opensecretmask not initialized; run `osm init`"}` for PostToolUse and exit 0. Exiting 1 here would let the original tool output flow through (since claude-code treats PostToolUse exit 1 as non-blocking) — exactly the leak we exist to prevent. The `osm hook` dispatcher catches missing-precondition errors at entry and translates them to direction-aware fail-closed responses before any data path runs.
  - For PreToolUse the same precondition failure emits `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"deny","permissionDecisionReason":"opensecretmask not initialized; run `osm init`"}}` and exits 0. We deny rather than fail-open here because if the engine isn't initialized we can't even know whether the tool input contains masks needing unmasking — defense in depth.
- **stderr**: log lines for `osm doctor` debugging; not used as a control channel
- **timing budget**: P50 < 30ms, P95 < 100ms, P99 < 300ms typical; up to ~100ms on 1MB outputs
- **failure policy is direction-aware** (fail-closed for mask via JSON `decision: block`, fail-open for unmask) — see §8.10

## 6. Detection

### 6.1 Three-layer cascade

Order: **registered values → regex rules → entropy heuristic**. First match wins.

```go
type Detector struct {
    registered *RegisteredSet  // .env values + manually-added (Aho-Corasick exact match)
    rules      []Rule          // ordered by specificity
    entropy    *EntropyScanner // optional, off by default
    allowlist  *AllowlistSet
}

type Finding struct {
    Start, End int
    Value      string
    Rule       string
    Confidence float64
}
```

### 6.2 Layer 1 — Registered values (exact match, Aho-Corasick)

Source: `.env`, `.env.*`, `.envrc` discovered by walking cwd up to git root; or `osm add NAME=value`.

Filtering at load time:
- Skip values < `min_secret_length` (default 8)
- Skip values in `[detector.allowlist] values`
- Skip keys in `[detector.env] ignore_keys` (`NODE_ENV`, `PATH`, etc.)

Highest confidence — if user said it's a secret, it is.

### 6.3 Layer 2 — Regex rules

Compiled-in gitleaks-derived rule set; user additions via `~/.opensecretmask/rules.toml`:

```toml
[[rule]]
id = "internal-svc-token"
pattern = '''svc_[A-Z][a-z0-9]{20,}'''
prefix_len = 4
charset = "alphanumeric"
min_len = 24
```

### 6.4 Layer 3 — Entropy heuristic

- Off by default (`config.toml: detector.entropy.enabled = false`)
- Activates on tokens not matched by layers 1–2, length ≥ `entropy.min_length` (default 24), Shannon entropy ≥ `entropy.threshold` (default 4.5 bits/char)
- Token boundary: `[\w\-_./+=]+`
- Charset for FPE: inherit from the matched token's actual charset

False-positive mitigation: confidence in audit log; `osm allow <value>` adds to allowlist.

### 6.5 Allowlist (`~/.opensecretmask/allowlist.json`)

```json
{
  "values": ["staging-token", "demo-key-123"],
  "patterns": ["^EXAMPLE_.*"],
  "rules_disabled": ["entropy-high"]
}
```

### 6.6 Detection performance

- Layer 1: Aho-Corasick automaton over registered values, single linear pass — O(n + matches)
- Layer 2: combined RE2 regex (Go stdlib `regexp`), linear time
- Layer 3: only on residual tokens, off by default
- Compiled-in rules and registered automaton cached to `~/.opensecretmask/cache/registered.aho` (gob-encoded), keyed by hash of registered values; rebuild on mismatch

Target: < 50ms scan on 1MB input.

### 7.4 Concurrency — flock + atomic rename

Single global lock file `~/.opensecretmask/.lock`.

Write protocol (every `secrets.json` / `mappings.json` mutation):
1. `flock(LOCK_EX)` with 5s timeout
2. Read current file
3. Merge new entry
4. Write to `<path>.tmp.<pid>.<rand>`
5. `fsync(tmp)`
6. `rename(tmp, real_path)` — POSIX atomic
7. `flock(LOCK_UN)`

Read protocol:
1. `flock(LOCK_SH)`
2. Read
3. `flock(LOCK_UN)`

`audit.log` uses `O_APPEND` + single `write()` of NDJSON line < 4KB — POSIX guarantees atomicity (PIPE_BUF=4096).

Failure modes:
- **Lock timeout** → direction-aware (in-memory fallback is unsafe across processes; the next hook is a fresh process and would not see an in-memory map):
  - **Mask path (write side)**: cannot persist new mapping → fail-closed per `[hooks.mask_on_error]` (deny or redact-all). Never emit a mask whose mapping wasn't durably written, because the next PreToolUse process will be unable to unmask it and the user's tool would execute with the mask string instead of the real value.
  - **Mask path (when value is already in mappings)**: the lock is only needed to write a *new* mapping. If the secret value is already mapped (lookup succeeded under shared read-lock before the write-lock attempt), masking proceeds with the existing mapping — no new write needed.
  - **Unmask path**: read-lock failure means we can't load the mapping table → fail-open (exit 0, no `updatedInput`). Tool runs with the mask string; fails loudly per §8.10.
  - audit.log records `action: "lock_timeout"` with direction and which file
- Stale lock → flock auto-released on process death (kernel-managed)
- Crash mid-rename → `.tmp.*` left behind; `osm doctor` cleans them up; real file untouched

Dep: `github.com/gofrs/flock` + `golang.org/x/crypto/hkdf`. No others.

### 7.5 Install / uninstall

`osm init`:
- Create `~/.opensecretmask/` (mode 700)
- Generate `install.key` from `crypto/rand`
- Write defaults: `config.toml`, `allowlist.json`, empty `secrets.json` and `mappings.json`
- Idempotent — refuses to overwrite unless `--force`

`osm install claude-code`:
- Locate `~/.claude/settings.json` (or `--global` / `--project`)
- Merge hook entries, preserving existing
- Print before/after diff
- `--dry-run` to preview

`osm uninstall claude-code`:
- Remove only entries tagged with `"description": "opensecretmask"`

### 7.6 Backup / portability

- `~/.opensecretmask/` is portable across machines: copy `mappings.json` and `secrets.json` (these contain the actual reverse-lookup data). `install.key` only matters if you want to *recompute* identical masks for new secrets on another machine.
- README guidance: treat the entire `~/.opensecretmask/` directory as sensitive — `mappings.json` IS your secrets in plaintext. Do NOT sync to cloud backups, shared volumes, or unencrypted external drives.

## 8. Edge Cases + Performance

### 8.1 Cold-start budget

| Component | Time |
|-----------|------|
| Process spawn (Go static, macOS) | ~5–8 ms |
| stdin JSON parse | <1 ms |
| Load config + allowlist | <2 ms |
| Load secrets.json (RLock + read) | <2 ms |
| Build/load Aho-Corasick automaton | 1–5 ms (lazy first use) |
| Compile combined regex rules | 1–3 ms |
| Scan 100KB output | <5 ms |
| Mappings update + atomic write | 5–10 ms |

Targets: P50 < 30ms, P95 < 100ms, P99 < 300ms.

### 8.2 Large outputs

**Never silent-passthrough**. Every byte either gets scanned or gets replaced — no leak through truncation. Naive fixed-overlap streaming is unsafe because PEM blocks, SSH private keys, multi-line JWTs, and base64-encoded large secrets routinely exceed any small constant.

**Two-layer streaming strategy**:

1. **Adaptive overlap** = `max(LongestRuleMaxLen, 4096)` bytes, computed from the compiled rule set at startup (each rule may declare a `MaxLen` hint; default 4 KB; PEM/SSH-key rules declare 16 KB). Set as a single number once, not guessed per-chunk.

2. **Multi-line container detection**: rules like `pem-private-key` and `ssh-private-key` carry `BeginMarker` / `EndMarker` strings (`-----BEGIN ... PRIVATE KEY-----` / `-----END ... PRIVATE KEY-----`). The streaming scanner runs a pre-pass that detects an open marker without a matching close marker inside the current window; when seen, it **suspends emission and keeps buffering** until the close marker arrives or the per-secret buffer hits `max_container_bytes` (default 1 MB). On overflow → fail-closed (deny / redact-all per §8.10), never flush the open container as plaintext.

Two distinct buffer allocations: `scanBuf` is a bounded ring (overwrite-safe — every byte already emitted or in trailing overlap to be re-scanned); `containerBuf` is a separate grow-only slice, allocated only when a container marker is open, bounded by `max_container_bytes`, fail-closed on overflow (body never flushed).

```
Stream(reader, writer):
  scanBuf       = ring(adaptiveOverlap + chunkSize)
  containerBuf  = nil                       # nil or growable []byte
  containerRule = nil
  scannedBytes  = 0

  loop:
    chunk, eof := reader.Read(64KB)
    if scannedBytes + chunk.size > max_scan_bytes:
      handleScanCap(remaining = chunk + reader.drain()); break
    scannedBytes += chunk.size

    # Path A: container open — append to grow-only buf, never to scanBuf
    if containerBuf != nil:
      containerBuf.append(chunk)
      if containerBuf.size > max_container_bytes:
        return failClosed("container exceeded max_container_bytes")
      end := indexOf(containerBuf, containerRule.EndMarker)
      if end >= 0:
        writer.Write(applyContainerMask(containerBuf, containerRule))
        containerBuf = nil; containerRule = nil
      else if eof:
        return failClosed("EOF inside open container; missing EndMarker")
      if eof: break
      continue

    # Path B: no container open
    scanBuf.append(chunk)
    for rule in containerRules:
      idx := indexOf(scanBuf, rule.BeginMarker)
      if idx >= 0:
        flushScan(scanBuf.head(idx), writer)        # head before marker → normal scan
        containerBuf  = scanBuf.tail_from(idx).clone()  # promote to grow-only buf
        containerRule = rule
        scanBuf.clear(); break

    if containerBuf == nil:
      if not eof:
        # Hold trailing overlap so straddling secrets aren't split
        scanLimit := scanBuf.size - adaptiveOverlap
        if scanLimit > 0:
          flushScan(scanBuf.head(scanLimit), writer)
          scanBuf.shift(scanLimit)
      else:
        # EOF: flush ENTIRE remaining buffer (no future chunks → no overlap needed).
        # Closes the leak where final < adaptiveOverlap bytes were silently dropped.
        flushScan(scanBuf.head(scanBuf.size), writer)
        scanBuf.clear()
    if eof: break

flushScan(bytes, writer):
  writer.Write(applyFindings(bytes, detector.Detect(bytes)))
```

**Buffer split rationale**: ring buffer with `max_container_bytes` capacity wraps before a long PEM closes — its body would silently overwrite. Separate grow-only `containerBuf` guarantees no byte inside an open container is overwritten before its EndMarker arrives.

**EOF flush rationale**: pre-fix loop only flushed `size - adaptiveOverlap` per iteration; post-EOF the final `< adaptiveOverlap` tail was never scanned. Fix flushes the full remaining buffer on EOF; mid-container EOF returns failClosed.

**Hard ceilings** (configurable):
- `max_scan_bytes` (default 50 MB) — total output bytes scanned per invocation
- `max_container_bytes` (default 1 MB) — single multi-line container size before declaring overflow
- On either cap exceeded, behavior driven by `on_scan_cap`:
  - `truncate` (default): replace remaining tail with `[opensecretmask: scan-cap exceeded — N bytes withheld]`. Truncated bytes never reach the LLM. audit.log records the event.
  - `deny`: PostToolUse returns `decision: "block"` — claude sees the block, no payload at all.

**Memory ceiling**: peak resident bytes ≤ `adaptiveOverlap + chunkSize + max_container_bytes` (~1.07 MB by default). Multi-GB outputs do not OOM. Container-buffer is the only large allocation and it short-circuits to fail-closed at its cap.

Each container rule must declare `MaxLen` as part of its rule definition, and that value participates in `LongestRuleMaxLen`. There is no path where "secret exists, body bigger than overlap, scanner missed it" — it's either fully buffered (containers) or fully covered by overlap (single-line tokens).

### 8.3 Binary content skip

Per `[hooks.skip_extensions]`, check `tool_input.file_path` extension before scanning. Extension-only check — fast and good enough for v1; content-sniffing deferred.

### 8.4 Encoded secrets

v1: plaintext-only detection. Documented limitation.
v1.1: optional decode-then-scan (try base64 if input looks base64ish; if finding, mask the encoded form).

### 8.5 Partial / split secrets

Out of scope. Each tool invocation is scanned in isolation.

### 8.6 Mask inside structured data (JSON, YAML, TOML, shell)

"Same length ⇒ structural validity" is **only** true if the mask body cannot emit format-meta characters (`"`, `'`, `\`, newline, backtick, `$`, `{`, `}`, `<`, `>`, `&`) that break JSON quoted strings / YAML block scalars / TOML strings / shell substitution / HTML attrs.

**Defense (v1)**: `Charset` enum restricted to alphabet + digit + `-` + `_` (Alphanumeric / Hex / Base64URL / AlphaUpper). All are subsets of unreserved JSON/YAML/TOML string + shell-safe identifier chars. `CharsetBase64` (with `+`, `/`, `=`) used only inside rules matching an already-base64 region (PEM bodies). `CharsetGeneric` removed; fallbacks (`env-import`, `entropy-high`) use Base64URL regardless of source charset. Mask cannot introduce a delimiter not already present.

**v1.1**: structured-format parser for `.json`/`.yaml`/`.toml` — locate string leaves, mask inside them, escape-correct.

**v1 limit**: secret containing escaped delimiters (e.g., `\"` inside JSON) keeps length but doesn't byte-for-byte preserve escaping topology. Structural validity intact (no new delimiters introduced); escaping round-trip closed in v1.1.

### 8.7 Model abbreviates the mask

`PreToolUse` only unmasks **exact** matches. Truncated mask → not unmasked → tool fails loudly (better than silent leak).
v1.1: `additionalContext` reminder when partial mask detected.

### 8.8 Mask collisions

Two collision classes, both handled in `Mask()` (§4.4):

1. **Self-collision** (`mask == real`): probability ~1/|charset|^bodyLen, vanishing for body ≥ 16. Re-derive with domain-separator byte appended to HKDF info.
2. **Cross-secret collision** (`mask` already in `mappings.by_mask` for a *different* real value): would silently corrupt reverse-lookup. `Mask()` reads `mappings.by_mask` (RLock) before inserting; on collision, re-derives with the next domain-separator. Bounded to 8 retries; if exhausted, returns `ErrMaskExhaustedRetries` and the hook fails closed (mask path) rather than register a corrupt mapping.

Never silently overwrite.

### 8.9 Re-entrancy guard

`OSM_RUNNING=1` env var checked at hook entry; exit 0 immediately if set. Defensive.

### 8.10 Failure modes — direction-aware

Asymmetric consequences → asymmetric policy:

| Direction | No-op-on-error worst case | Policy |
|-----------|---------------------------|--------|
| Mask (PostToolUse) | Output with secrets reaches LLM — silent leak | **Fail-closed** |
| Unmask (PreToolUse) | Tool gets mask string → fails loudly. No leak | **Fail-open** |
| Observe (UserPromptSubmit) | Fail to warn. Prompt unchanged either way | Fail-open (no-op) |

**Mask fail-closed** (controlled by `[hooks.mask_on_error]`):
- `"deny"` (default): JSON `{"decision":"block","reason":"opensecretmask: scanner failed (<short>); blocking output to prevent leak"}`
- `"redact-all"`: JSON `updatedToolOutput` with all scannable content replaced by `[opensecretmask: scanner failed — content withheld]`, same shape as input

Original payload **never** forwarded on error.

**Unmask fail-open**: exit 0, no `updatedInput`. Tool runs with mask string; fails (e.g. `curl -H "Authorization: Bearer sk_live_X9k…"` → 401). LLM never had real value, no leak.

**Always**:
1. Append audit.log `action: "error"`, direction, trace, `policy_applied`
2. Stderr short message (debug only, not control)
3. No `panic` to OS — recover at hook entry, translate to deny/passthrough
4. **Always exit 0** with appropriate JSON. Exit 1 reserved for CLI misuse before payload read (§5.5). Exiting 1 from fail-closed mask handler would leak (PostToolUse exit 1 = non-blocking).

### 8.11 Observability

- `osm status` — counts of registered secrets, mappings cached, audit lines, last activity
- `osm doctor` — integrity checks: file modes, lock health, mappings consistency, key presence
- `osm tail` — live tail of audit.log

## 10. Security Model

### 10.1 What we DO defend against

| Threat | Defense |
|--------|---------|
| Secret in tool output goes to LLM | PostToolUse mask via `updatedToolOutput` |
| LLM emits real secret in code/command (no prior exposure) | LLM never saw real value, only the mask. Mask is HMAC-derived and one-way without `install.key`; LLM cannot derive a real value from a mask alone. PreToolUse unmasks known mask strings before exec. |
| Concurrent sessions corrupt state | flock + atomic rename |
| Audit log becomes a credential dump | Audit stores truncated mask (12 chars) + rule ID; never real values |
| Hook crash blocks claude | Fail-closed for mask, fail-open for unmask (§8.10); never `panic` to OS |
| Tool output silently truncated → tail leaks | Stream-scan whole output up to `max_scan_bytes`, then truncate-replace the tail (§8.2) |

### 10.2 What we do NOT defend against (documented)

| Out of scope | Why |
|---|---|
| **Plaintext secrets at rest** | `secrets.json` and `mappings.json` store real values in plaintext, protected by chmod 600 + dir 700 + filesystem ACL. **Anyone with read access to `~/.opensecretmask/` reads the secrets directly — `install.key` is not required for that path.** v1 trades at-rest encryption for simplicity; v1.1 plan: optional keychain-backed vault. Use `psst`/1Password for true vaulting. |
| Secret already in conversation history before install | Run `osm install` before pasting secrets — we cannot time-travel |
| User pastes raw secret in prompt | claude-code's `UserPromptSubmit` cannot rewrite prompt content; warn-only |
| Encoded secret (base64, hex, gzip) | v1 plaintext-only detection; v1.1 may add decode-and-scan |
| Split secret across two tool invocations | Each invocation scanned in isolation |
| Compromise of local machine | This is a leak-prevention layer, not a vault. If attacker has read on `~/.opensecretmask/`, they have your secrets. |
| Side-channel via mask length / format | Format-preserving by design — preserves length and charset class. Documented tradeoff. |
| Rogue tool exfiltrating directly via network | Hooks see what reaches the LLM, not what local tools do over the network |
| Mask reverse-engineering by attacker who has only the mask | Computationally infeasible without (a) `install.key` AND (b) candidate plaintext to verify against. HMAC is one-way; brute force needs a guessing oracle. |
| Mask reversal by anyone with `mappings.json` | **Trivial — `mappings.json` IS a forward+reverse map of mask↔real.** Protect it with chmod 600. |

README must surface this list prominently.

### 10.3 Permissions

- `osm doctor` checks all file modes + dir mode every run; auto-repairs to 600/700 on drift
- Refuses to operate if `~/.opensecretmask/` is world- or group-readable
- Refuses to write `install.key` if directory not 700

### 10.4 Audit log integrity

NDJSON append-only. Rotation via `osm doctor --rotate-audit` archives + gzips, never edits in place.
Tamper-evident chain (`prev_hash`) — design hook for v1.1+; not implemented v1.

- `osm init`, `osm install claude-code`, `osm doctor`, `osm scan <file>`, `osm hook` dispatcher
- claude-code adapter (PostToolUse + PreToolUse + UserPromptSubmit + SessionStart)
- 3-layer detector (.env + ~30 regex + entropy-off-by-default)
- FPE mask via HMAC-SHA256 + HKDF-Expand
- mappings.json + secrets.json with flock + atomic write
- audit.log NDJSON
- Tests for all of the above
- macOS + Linux

### v1.1 (nice-to-have)
- Encoded-secret detection (base64-decode-then-scan)
- Blocked-file PreToolUse deny list (redmem-style: refuse to even Read certain paths)
- PostToolUse Edit/Write residual-scan safety net
- opencode adapter + npm package
- Keychain-backed install.key option
- Tamper-evident audit log (`prev_hash` chain)
- `osm tail`, `osm allow`, `osm rotate-key`

### v2.0 (vision)
- pi-agent + other harness adapters
- Team-shared mappings (encrypted sync)
- TUI dashboard for live mask events
- Pluggable detection (gitleaks rule live-update)
- Windows support
